# Build and deployment

Note Nerds ships from a local Python command patterned after TripMaster. XcodeGen defines the project structure, Doppler provides release values, and GitHub checks code changes.

## Current release target

- Product: Note Nerds
- Platform: iOS and iPadOS
- Minimum version: iOS and iPadOS 26.0
- Device family: iPhone and iPad
- Bundle identifier: `com.strategicnerds.notenerds`
- CloudKit container: `iCloud.com.strategicnerds.notenerds`
- Apple Developer team: `955GSY56UT`
- Marketing version: `1.0.1`
- Current TestFlight build: `35`
- Release mode: manual after approval

Apple provides no App Store capability that exactly identifies Apple Intelligence-capable hardware. Note Nerds declares no substitute capability. Features that depend on Apple Intelligence must check their framework availability at runtime.

Before using folder icons or colors in a Notion-connected library, install build 15 or later on every connected device. Build 14 can republish the version 1 manifest without folder appearance fields and remove those fields from the shared backup.

## One-time Apple setup

Complete these steps after creating the app in App Store Connect.

### Configure the App ID

1. Open Certificates, Identifiers & Profiles in the Apple Developer portal.
2. Confirm `com.strategicnerds.notenerds` is registered as an explicit App ID.
3. Enable iCloud and CloudKit.
4. Select or create `iCloud.com.strategicnerds.notenerds`.
5. Confirm the container is assigned to the App ID for development and distribution.

The entitlement file is `NoteNerds/NoteNerds.entitlements`.

### Create the App Store Connect record

Use these values:

| Field | Value |
| --- | --- |
| Platform | iOS |
| Name | Note Nerds |
| Primary language | English (U.S.) |
| Bundle ID | `com.strategicnerds.notenerds` |
| SKU | `NOTENERDS-IOS-001` |
| User access | Full Access |

Record the numeric Apple ID shown under App Information. It becomes `ASC_APP_ID`.

### Configure the App Store Connect API key

1. Reuse the App Store Connect key used by TripMaster.
2. Store its Key ID and Issuer ID in Doppler.
3. Save its `.p8` file locally as `~/.private_keys/AuthKey_<ASC_KEY_ID>.p8` with file mode `600`.

## Doppler setup

The Doppler CLI must be authenticated before it can create the project:

```bash
doppler login
./scripts/setup-doppler.sh
```

Then store the release values:

```bash
doppler secrets set ASC_KEY_ID="<key id>" \
  --project notenerds --config prd

doppler secrets set ASC_ISSUER_ID="<issuer id>" \
  --project notenerds --config prd

doppler secrets set ASC_APP_ID="<numeric Apple ID>" \
  --project notenerds --config prd

doppler secrets set NOTION_CLIENT_ID="<Notion client id>" \
  --project notenerds --config prd

doppler secrets set NOTION_CLIENT_SECRET="<Notion client secret>" \
  --project notenerds --config prd
```

Do not add empty or sample values. The release preflight should fail until the real values exist.

Set `http://localhost:53117/oauth/notion` as the exact redirect URI for the public Notion integration. The release command injects encoded client values through the `xcodebuild` child process environment. They do not appear in command arguments or build logs.

```bash

```

```bash
./scripts/ship.py testflight \

```

## First App Store release

The first upload should stop before automated review submission:

```bash
./scripts/ship.py app-store \
  --version 1.0.0 \
  --notes "Initial release." \
  --skip-submit
```

In App Store Connect:

1. Wait for build processing.
2. Preview the tracked text with `./scripts/ship.py metadata --version 1.0.0`.
3. Upload it with `./scripts/ship.py metadata --version 1.0.0 --upload`.
4. Upload the required iPhone and iPad screenshots.
5. Complete App Privacy, age rating, pricing, availability, content rights, and App Review contact fields.
6. Add the processed build to version 1.0.0.
7. Confirm the version shows Ready for Review.

After one manual submission succeeds, the local command can submit later versions through the App Store Connect API.

## Later App Store releases

Run the local command with the new version and release notes:

```bash
./scripts/ship.py app-store \
  --version 1.1.0 \
  --notes "Customer-facing changes."
```

## Release record

After a successful upload, update `project.yml` to the shipped version and build, then commit and tag it:

```bash
git add project.yml NoteNerds.xcodeproj
git commit -m "Release Note Nerds 1.0.0"
git tag v1.0.0
git push origin main --follow-tags
```

## Failure recovery

- Archive failure: read `dist/archive-<version>-<build>.log`.
- Export failure: verify the team, API key role, keychain access, App ID, and iCloud entitlement.
- Upload failure: search the reported `ITMS` code and correct the named metadata or bundle issue.
- Build processing failure: check Apple’s processing email and the TestFlight build page.
- Submission failure after upload: attach the uploaded build and submit it through App Store Connect.
- Duplicate build number: run the local command again. It assigns the next build number.

The release command never stores passwords or private keys in the repository. `dist/`, `.env`, `.p8`, and the managed Python environment are ignored.
